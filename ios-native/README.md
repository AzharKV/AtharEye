# Athar Eye — native iOS (SwiftUI) comparison app

A focused **visual + performance comparison** port of the finished Athar Eye PWA (`../pwa`), built in
**pure SwiftUI** (SwiftUI App lifecycle, `@main`, no third-party deps). It exists so the team can weigh
native SwiftUI feel against the **React Native** app (`../reactnative`) and the **Flutter** app
(`../flutter`) — same locked navy `#0C0F12` + teal `#14B8C0` design, same demo data.

This is **not** the full 13-screen product. It is the **3 hero screens** that best show off native
rendering, plus two simple stubs.

## What's included
- **Projects** (`ProjectsScreen.swift`) — large title, portfolio summary card (teal **progress ring**
  with the avg % + On track / Review / Complete counts), single-select filter **chips** (All / On site /
  Needs review / Complete, live-filtering), and project **cards** (mini ring + name + location · m² · scans
  + status badge + chevron). Tapping a card pushes the Report detail via `NavigationStack`.
- **Report detail** (`ReportDetailScreen.swift`) — branded header (teal mark + "Athar**Eye** ·
  PROGRESS REPORT"), the **count-up coverage Donut** hero (a trimmed `Circle` stroked with an angular
  teal→`#45D6DD` gradient on a faint-red track, rotated −90°, **counting 0 → pct over ~1.1s** on appear),
  Covered / Missing m² tiles, and a coverage-by-room list (grey bars, **red** when a room is < 45%).
- **Active scan** (`ScanActiveScreen.swift`) — the **performance showcase**. A teal **LiDAR point cloud**
  building up over ~7s, drawn with `TimelineView(.animation) { Canvas { … } }` for per-frame 60fps
  rendering: ports `makePoints(2000)` + the 1-point-perspective projection from the PWA's `ScanFlow.tsx`
  (floor / ceiling / walls / back wall, revealed in random order, depth-shaded teal points, a faint
  perspective room wireframe that fades in). Overlays a pulsing "SCANNING" pill, live stats
  (Points {p·1.84}M / Coverage / Tracking Strong), a teal progress bar, and a round stop button.
  Auto-finishes at 100%. Opened from the centre Scan tab as a `fullScreenCover`.
- **Reports** and **Settings** tabs are simple stubs (not the comparison focus).

The comparison centrepieces are the **donut count-up** and the **Canvas point cloud**.

### Deliberately out of scope
Iso-massing / BIM sheets, search, persistence, the scan project-picker / guidance / processing / result
steps, new-project creation, share sheets, and the other 10 PWA screens. No live camera (the scan uses the
PWA's gradient fallback backdrop). No networking.

## Requirements
Xcode 26.5 · Swift 6 · iOS deployment target 17.0+ · **xcodegen** (`brew install xcodegen`).

## Regenerate the Xcode project
The `.xcodeproj` is generated from `project.yml` — never hand-edit it. After changing `project.yml`
or adding/removing files under `Sources/`:
```bash
cd ios-native
xcodegen generate
```

## Build & run
Open in Xcode and run on the **iPhone 16 Pro** simulator:
```bash
open ios-native/AtharEyeCompare.xcodeproj
```
…or build from the command line. **Note:** this machine has two *iPhone 16 Pro* simulators (iOS 18.2 and
18.6), so a bare `name:iPhone 16 Pro` destination is ambiguous — pin the OS (or use a device `id`):
```bash
cd ios-native
xcodebuild \
  -project AtharEyeCompare.xcodeproj \
  -scheme AtharEyeCompare \
  -sdk iphonesimulator \
  -destination 'platform=iOS Simulator,name=iPhone 16 Pro,OS=18.6' \
  build
```
This is verified to end with **`** BUILD SUCCEEDED **`**. (`xcrun simctl list devices available` shows
the installed runtimes if 18.6 isn't present.)
